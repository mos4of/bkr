## ✨ Особливості

### 🎨 Сучасний інтерфейс
- **CustomTkinter GUI** з темною темою (Dark Mode)
- **Анімації** через threading + after() в tkinter
- **Splash screen** при запуску (2.5 секунди)
- **Кастомні прогрес-бари** з кольоровими індикаторами
- **Термінальний стиль** логів (Consolas, зелений текст)
- **Інтерактивні картки** методів знищення

### 🔧 Три режими роботи

#### РЕЖИМ 1: Файл
- Знищити один конкретний файл обраним методом
- Вибір з 4 методів: NIST Clear, NIST Purge, Crypto Erase, Verify Only
- Верифікація після знищення

#### РЕЖИМ 2: Папка
- Рекурсивне знищення всіх файлів у папці
- Показує прогрес: "Файл 12 з 47: report.docx"
- Видалення порожніх папок після знищення

#### РЕЖИМ 3: Диск
- Аналіз вільного простору на диску
- Заповнення вільного простору тимчасовими файлами
- Автоматичне очищення після заповнення

### 🛡️ Безпека та підтвердження
- ⚠️ Підтвердження перед кожною операцією
- 🔐 Подвійне підтвердження для Crypto Erase
- ⚠️ Перевірка прав адміністратора для NIST Purge
- ⚠️ Автоматична перевірка BitLocker для Crypto Erase
- ✅ Верифікація після кожного знищення
- ✅ Детальне логування з посиланнями на стандарти

## 📊 Методи знищення

### 🔵 NIST Clear (рівень Clear)
- **Стандарт:** [NIST SP 800-88r1](https://csrc.nist.gov/publications/detail/sp/800-88/rev-1/final), Section 2.4
- **Прохідів:** 1
- **Дані:** Псевдовипадкові байти (`os.urandom`)
- **Опис:** Один прохід запису псевдовипадкових даних. Захищає від відновлення стандартними програмними засобами.
- **Для кого:** HDD та USB-накопичувачі, що залишаються в організації або передаються в межах неї.
- **Примітка:** Ранішній метод запису нулів (zeros) не відповідає вимогам NIST Clear, оскільки не забезпечує криптографічної нечитаємості.

### 🔴 NIST Purge (рівень Purge)
- **Стандарт:** [NIST SP 800-88r1](https://csrc.nist.gov/publications/detail/sp/800-88/rev-1/final), Section 2.5; [IEEE 2883-2022](https://standards.ieee.org/ieee/2883/2022/)
- **Реалізація:** Апаратна команда контролера диска
- **Windows:** `diskpart` → `clean all`
- **Linux:** `hdparm --security-erase` (ATA SE) або `nvme format --ses=1` (NVMe Sanitize)
- **Опис:** Знищує всі дані включно з резервним простором (SSD over-provisioning), кешем контролера та хост-захищеними областями (HPA/DCO).
- **Для кого:** SSD та HDD, що виводяться з експлуатації або передаються третім особам.
- **⚠️ Потребує прав адміністратора**
- **⚠️ Незворотна операція — усі дані на диску буде знищено!**

### 🟣 Crypto Erase (криптографічне знищення)
- **Стандарт:** [IEEE 2883-2022](https://standards.ieee.org/ieee/2883/2022/), Section 7; [NIST SP 800-88r1](https://csrc.nist.gov/publications/detail/sp/800-88/rev-1/final)
- **Прохідів:** 0 (миттєво!)
- **Принцип:** Знищення ключа шифрування → дані стають криптографічно недоступними назавжди без перезапису секторів.
- **Для кого:** Диски з увімкненим BitLocker або самошифруванчі диски (SED).
- **⚠️ Лише для дисків із увімкненим BitLocker**
- **⚠️ Потребує подвійного підтвердження**
- **Перевага:** Найшвидший метод. Не створює зносу на SSD.

### 🟢 Verify Only (перевірка)
- **Опис:** Перевірка чистоти носія без знищення
- **NIST Clear:** Зчитує 1000 випадкових секторів, перевіряє відмінність від оригіналу
- **NIST Purge:** Зчитує ключові сектори (початок/кінець/випадкові), перевіряє заповнення нулями
- **Crypto Erase:** Перевіряє статус BitLocker (має бути вимкнений)

## 📜 Посилання на стандарти

| Стандарт | Назва | Посилання |
|----------|-------|-----------|
| NIST SP 800-88r1 | Guidelines for Media Sanitization | [PDF](https://csrc.nist.gov/pubs/sp/800-88/r1/final) |
| IEEE 2883-2022 | IEEE Standard for Sanitizing Storage | [IEEE Xplore](https://standards.ieee.org/ieee/2883/2022/) |

### Ключові зміни від NIST SP 800-88r1
- **Clear** (раньше "overwrite"): захист від програмного відновлення, 1 прохід псевдовипадкових даних
- **Purge** (раньше "degauss/destroy"): апаратне знищення, яке охоплює всі області носія
- **Destroy**: фізичне знищення носія (не реалізовано — потребує спеціального обладнання)

### Чому DoD 5220.22-M та Гутман більше не рекомендуються
- **DoD 5220.22-M** був скасований самим Міноборони США у 2001 році (NIST SP 800-88 замінив його у 2006, оновлений у 2023)
- **Схема Гутмана** (35 проходів) була розроблена для магнітних дисків 1990-х; автор визнав її надлишковою для сучасних носіїв
- Сучасні SSD мають wear leveling, over-provisioning та кеш контролера, які роблять багатопрохідне перезаписування марним

1. **Виберіть режим** — Файл / Папка / Диск
2. **Виберіть метод** — NIST Clear / NIST Purge / Crypto Erase / Verify Only
3. **Виберіть ціль** — натисніть 📁 або перетягніть файл/папку

6. **Спостерігайте** — за прогресом у реальному часі
