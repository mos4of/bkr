# SecureWipe Pro

Програмний засіб безпечного знищення даних на носіях інформації.
Реалізує рівні Clear і Purge за NIST SP 800-88r2 та IEEE 2883-2022.
Платформа: Windows 10/11 (64-bit), NTFS. Версія 1.0.0.

---

## Призначення

Знищення даних під час виведення з експлуатації апаратно-програмних засобів.
Метод знищення обирається адаптивно за рівнем ризику активу та станом шифрування носія.
Кожна операція завершується автоматичною верифікацією, записом до журналу та формуванням сертифіката PDF.

---

## Вимоги

- Windows 10/11 (64-bit), файлова система NTFS
- Python 3.10 і вище (тестовано на 3.11.3)

Модулі:

## Методи знищення

### NIST Clear (рівень Clear)

- Один прохід запису псевдовипадкових даних через `os.urandom()`.
- Блок 65536 байт, після запису — `os.fsync()`.
- Перезаписує лише логічно адресований простір файлу.
- Призначення: низький рівень ризику; HDD та USB у межах організації.

### NIST Purge (рівень Purge)

- Windows: `diskpart` → `select volume X` → `clean all`.
- Linux: `nvme format --ses=1` (NVMe) або `hdparm --security-erase` (ATA).
- Обнуляє весь фізичний диск разом із таблицею розділів.
- Носій після операції потребує повторної ініціалізації та форматування.
- Призначення: середній і високий рівень ризику; незашифровані носії.
- Потребує прав адміністратора. Незворотна операція.

### Crypto Erase (рівень Purge за IEEE 2883-2022)

- Знищення ключа шифрування BitLocker.
- Перевірка стану: `Get-BitLockerVolume` (PowerShell).
- Виконання: `Remove-BitLockerKeyProtector` → `manage-bde -off`.
- Час не залежить від обсягу тома (кілька секунд).
- Призначення: високий рівень ризику; зашифровані томи BitLocker.
- Доступний лише для томів зі станом FullyEncrypted. Потребує подвійного підтвердження.

### Verify Only

- Аналіз ентропії секторів без зміни даних.
- Звіт про поточний стан носія.

Рівень NIST Destroy (фізичне знищення) програмно не виконується — засіб лише інформує про його потребу.

## Алгоритм роботи

1. Вибір об'єкта (файл / папка / логічний том).
2. Визначення рівня ризику оператором (низький / середній / високий).
3. Формування профілю знищення з урахуванням стану шифрування.
4. Вибір методу: рекомендований за профілем, підтверджується оператором.
5. Виконання процедури знищення.
6. Автоматична верифікація результату.
7. Документування: запис журналу, SHA-256 запису, сертифікат PDF.

Несумісні конфігурації виявляються до запуску: брак прав адміністратора для Purge або незашифрований диск для Crypto Erase блокують операцію з попередженням у статусному рядку.

---

## Верифікація

| Метод | Алгоритм | Вибірка | Критерій успіху |
|-------|----------|---------|-----------------|
| NIST Clear | Унікальні байти у блоці 64 КБ | до 1000 секторів | ≥ 95 % секторів з >10 унікальних байтів |
| NIST Purge | Перевірка секторів на нуль | до 100 крайових + 800 випадкових | 100 % секторів дорівнюють нулю |
| Crypto Erase | Стан BitLocker через PowerShell | системний виклик | захист вимкнено, ключ знищено |
| Verify Only | Аналіз ентропії | до 1000 секторів | звіт без зміни даних |

Верифікація запускається автоматично після кожної операції без дій оператора.

---

## Журнал операцій

Запис до `logs/` після кожної операції містить: стандарт, метод, об'єкт, розмір, тривалість, результат верифікації, статус. Цілісність запису контролюється хешем SHA-256.

---

## Обробка нештатних ситуацій

| Ситуація | Реакція |
|----------|---------|
| Диск не знайдено | Повідомлення, операція не починається |
| Purge без прав адміністратора | Блокування запуску |
| Crypto Erase: диск не зашифровано | Блокування, пропонується Clear або Purge |
| Верифікація < 95 % | Іконка ✘, рекомендація повторити |
| Виняток під час операції | Журналюється, GUI повертається в робочий стан |
| Диск заповнено (заповнення простору) | Цикл завершується, temp-файли видаляються |

Жодна нештатна ситуація не призводить до аварійного завершення: винятки перехоплюються у worker-потоці.

## Попередження

- Знищення даних безповоротне. Робіть резервні копії важливого.
- NIST Purge стирає ВСІ дані на диску, включно з системними.
- Crypto Erase вимагає попереднього шифрування тома BitLocker.
- Знищення системного диска неможливе в межах запущеної ОС.
